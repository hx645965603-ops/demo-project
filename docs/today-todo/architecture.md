# 「今日待办」第一版技术架构方案

状态：已锁定（2026-11-19 用户拍板），桌面客户端工程师可按此开发。  
仓库：https://github.com/hx645965603-ops/demo-project  
界面稿：

- `deliver-01-menubar.png` 菜单栏入口
- `deliver-02-list.png` 列表弹窗
- `deliver-03-empty.png` 空状态

第一版范围（已确认）：仅 macOS；本地存储；无账号、云同步、提醒、多日日历。昨日已完成项保留在本地文件中、今天不再显示；界面锁定浅色；不做改标题和拖拽排序。

---

## 1. 推荐技术栈及理由

| 层级 | 选型 | 理由 |
| --- | --- | --- |
| 语言 / 框架 | Swift + SwiftUI | 仅做 macOS 菜单栏小工具，原生控件、字体、阴影和 SF Symbols 最容易对齐已确认视觉稿，包体小、无需额外部署运行时。 |
| 菜单栏与弹窗 | 优先 SwiftUI `MenuBarExtra` + `.menuBarExtraStyle(.window)`；若窗口定位、圆角阴影或图标选中高亮无法对齐稿件，再用 AppKit `NSStatusItem` + `NSPopover` | `MenuBarExtra` 开发更快；稿中弹窗紧贴图标下方、打开时图标有圆角高亮，这是系统菜单栏 Extra 的标准行为，必要时用 AppKit 精确控制。 |
| 图标 | SF Symbols：菜单栏用 `checkmark.circle`（template 单色）；完成态用 `checkmark.circle.fill`；添加用 `plus`；删除用 `xmark` | 与稿中圆圈打勾、菜单栏其它系统图标风格一致，菜单栏图标随系统菜单栏着色；弹窗本身第一版锁定浅色，不随系统深色模式切换。 |
| 本地存储 | `Codable` JSON，写入应用容器内 Application Support，采用临时文件写入再原子替换 | 数据量很小；实现和测试都直观；崩溃时不易写成半截文件。第一版不必上 Core Data / SwiftData。 |
| 应用形态 | Accessory 应用（`LSUIElement` / `NSApplication.ActivationPolicy.accessory`） | 只出现在菜单栏，Dock 无图标，关闭弹窗不等于退出；符合「点击图标弹出紧凑悬浮窗」的产品形态。 |
| 最低系统 | macOS 13 Ventura | `MenuBarExtra` 从 13 起可用。若需覆盖更早系统，再改为纯 AppKit，不作为第一版目标。 |
| 构建与提交 | Xcode 原生工程，产物为 `.app`，代码提交至上述 GitHub 仓库 | 与桌面客户端工程师职责（窗口、权限、安装打包、提交仓库）一致。 |

不采用 Electron / Tauri / 独立 Web 前端：体积大，菜单栏弹出、材质和间距很难对齐这三张稿，且第一版没有跨平台需求。因此第一版不需要前端工程师单独参与实现。

权限：写入沙盒内 Application Support，不申请辅助功能、通知、全盘访问等权限。

## 2. 模块划分

```
今日待办.app
├── AppShell          应用入口、accessory 策略、菜单栏图标、弹窗开关与点击外部关闭
├── TodayUI           与三张稿一一对应的界面
│   ├── MenuBarIcon   圆圈打勾入口，打开时系统选中高亮
│   ├── TodayHeader   「今天」+「M月d日 星期X」
│   ├── TodoList      未完成在上、已完成在下
│   ├── TodoRow       勾选圆圈、标题、悬停删除
│   ├── EmptyState    「今天还没有待办」引导
│   └── AddTodoBar    「+ 添加待办…」，回车新增
├── Domain            待办模型、列表分组与排序规则（纯逻辑，不碰 UI）
├── Persistence       JSON 仓储：加载、原子保存
└── DayRollover       跨日处理：监听日历日变化，刷新「今天」可见列表
```

依赖方向：`TodayUI` → `Domain` → `Persistence`；`DayRollover` 只通知 Domain / 仓储刷新。UI 不直接读写文件。

## 3. 数据模型

```swift
struct TodoItem: Identifiable, Codable, Equatable {
    var id: UUID
    var title: String
    var isCompleted: Bool
    var createdAt: Date
    var completedAt: Date?
    var sortOrder: Int
}

struct TodoStoreFile: Codable {
    var schemaVersion: Int   // 第一版为 1
    var items: [TodoItem]
}
```

存储位置建议：`~/Library/Application Support/<Bundle ID>/todos.json`（沙盒内对应路径）。

### 「今天」的可见规则

用系统当前时区的日历日（`Calendar.current`，不要写死时区）：

- **未完成**：全部 `isCompleted == false` 的项，无论哪天创建，均出现在今日列表上方，按 `sortOrder` 升序。这就是「第二天未完成项自动带到今天」。
- **已完成**：仅展示 `isCompleted == true` 且 `completedAt` 落在今天的项，放在未完成项下方，按完成时间或 `sortOrder` 排列。
- **昨日及更早已完成的项**：仍保留在 JSON 中，但不在「今天」列表展示。第一版不做历史回顾，也不物理删除，方便以后扩展。
- **空状态**：今日可见的未完成 + 今日已完成都为空时，显示空状态稿；若今天全部完成但仍有今日已完成项，显示列表稿而不是空状态。

跨日触发：弹窗每次打开时检查一次；并监听 `NSCalendar.dayChangedNotification`（进程未退出、日切跨过午夜时也能更新）。

### 已锁定的交互细节

- 新增：标题去首尾空格，空字符串不写入；新项追加到未完成分组末尾。
- 勾选完成：该项立即下沉到已完成分组，标题变灰并加删除线。
- 取消完成：回到未完成分组末尾。
- 删除：悬停显示 ×，点击立即删除，无二次确认。
- 第一版不做（已确认）：改已有标题、拖拽排序；快捷键仅支持回车新增、Esc 关闭弹窗。

## 4. 与三张界面稿的对应实现要点

### deliver-01-menubar.png（菜单栏入口）

- 菜单栏左侧（控制中心 / 电池等系统图标一侧）放置 template 图标：线条圆圈 + 对勾，粗细、大小与相邻系统图标接近，不要用彩色或填充态。
- 未打开时无额外底衬；这是默认态。
- 点击图标打开弹窗；再点一次或点击弹窗外关闭。应用本身继续驻留在菜单栏。
- 关掉再开（含退出应用后再次启动）：从 JSON 恢复数据，列表不应空白，除非本来就没有今日可见项。

### deliver-02-list.png（列表弹窗）

- 紧凑悬浮窗，宽度约 280–320 pt，圆角约 12–16 pt，浅色背景、轻阴影，锚在菜单栏图标正下方。
- 打开时，菜单栏图标出现系统风格的圆角选中底（稿中图标背后的浅灰圆角矩形）。
- 顶栏：「今天」粗体大标题；下一行次要灰色「M月d日 星期X」，例如「11月19日 星期四」，用本地化中文格式，随系统日期更新。
- 未完成项：浅灰空心圆 + 深色标题，自上而下排列。
- 悬停某一行：行背景变为浅灰圆角矩形，右侧出现灰色 × 删除按钮；未悬停时不显示删除。
- 已完成项：蓝色实心圆白对勾（`checkmark.circle.fill` + 系统蓝），标题灰色删除线，位于未完成项下方。
- 底栏用细分隔线隔开，左侧 `+`，占位符「添加待办...」；焦点在输入框，回车新增并清空输入。
- 列表区域可滚动，避免待办增多后撑破紧凑弹窗。

### deliver-03-empty.png（空状态）

- 顶栏和底栏与列表稿完全同一套组件，不要做两套窗口。
- 中间居中：浅灰圆角方底 + 对勾图标；主文案「今天还没有待办」；辅文案「在下方输入，按回车即可添加」。
- 空状态不替代底部输入框，引导用户使用同一条「添加待办...」。

视觉策略（已确认）：第一版锁定浅色以对齐稿件；系统深色模式作为后续迭代，不纳入第一版。
